## 2. 核心流程

```text
创建匿名 Session
→ 八步分步保存
→ 中断后恢复进度
→ 服务端完成计算
→ Free Result
→ 幂等 Demo 支付
→ Full Result
```

- 身份来自 HttpOnly Session Cookie，客户端不能通过 body 选择 Session。
- 分步答案保存到 PostgreSQL，`GET /api/session` 恢复答案、完成步骤、版本和下一步。
- 完成时由服务端计算并持久化 BMI、BMR、TDEE、建议摄入量、目标日期和预测曲线。
- Free DTO 由服务端允许字段白名单构建，Full 保护字段不会进入 Free JSON、HTML 或 DOM。

## 3. API 与数据模型

| API | 方法与路径 | 用途 |
|---|---|---|
| API-01 | `POST /api/sessions` | 创建/复用匿名 Session 和首个 Assessment |
| API-02 | `GET /api/session` | 恢复当前服务端状态 |
| API-03 | `PATCH /api/assessments/:id/steps/:step` | 版本化分步保存 |
| API-04 | `POST /api/assessments/:id/complete` | 计算并持久化 Result |
| API-05 | `GET /api/assessments/:id/result` | 返回严格 Free 或 Full DTO |
| API-06 | `POST /api/pay` | 幂等同步 Demo 支付 |
| API-07 | `POST /api/assessments` | 新建/复用 Assessment |
| API-08 | `GET /api/health` | 应用与数据库健康检查 |
| API-09 | `POST /api/demo/session-exchange` | review code 换取固定已付费 Cookie |

核心关系：Session 拥有 Assessment、Payment 和当前 Subscription；Assessment 完成后产生一个 AssessmentResult；Payment 是幂等事件证据，Subscription 是当前权益。详细 ER 图和约束见 [`architecture/data-model.md`](architecture/data-model.md)。

## 4. `/pay` 与固定已付费 Session

- 相同 Session + 相同幂等键 + 相同 Assessment 返回第一次支付结果。
- 相同键改用于另一 Assessment 返回 `409 IDEMPOTENCY_KEY_REUSED`。
- Payment 写入和 Subscription 激活位于同一事务；失败整体回滚。
- PostgreSQL advisory transaction lock 和唯一约束防止并发首次支付产生重复权益。
- 支付后 Result 重新获取失败时，前端复用原幂等键；页面整体刷新后，数据库中的 `ACTIVE` Subscription 仍可恢复 Full 权益。

固定演示记录：

| 实体 | 固定 ID | 状态 |
|---|---|---|
| Session | `10000000-0000-4000-8000-000000000001` | 未过期，拥有 `ACTIVE` Subscription |
| Assessment | `20000000-0000-4000-8000-000000000001` | `COMPLETED` |
| AssessmentResult | `30000000-0000-4000-8000-000000000001` | 已存在 |
| Payment | `40000000-0000-4000-8000-000000000001` | `SUCCEEDED`, `provider=DEMO` |
| Subscription | `50000000-0000-4000-8000-000000000001` | `ACTIVE` |

Assessment 本身没有“已支付”字段；权益属于 Session 的 Subscription。Session/Assessment ID 可以公开，review code 必须私密交付，Session token 永不交付。完整 cURL 见 [`guides/api-walkthrough.md`](guides/api-walkthrough.md)。

## 6. AI 使用与已知限制

AI 用于 PRD/P0 拆解、Schema 方案比较、Mock 与边界用例、API 防护、回滚/并发测试、E2E 脚手和证据追溯。公式、迁移、数据库约束、密钥处理、真实测试和最终验收由人工复核。

被否决的 AI 建议包括通用 EAV 问卷模型、仅客户端遮挡 Full 字段、字符串化预测曲线和 Serverless 进程内限流。它们分别会弱化类型/跨字段验证、将界面遮挡误当授权、丢失 JSON 结构，或无法跨实例共享状态。

已知限制：匿名 Demo 而非医疗产品；同步模拟支付而非真实支付平台；无用户自助删除、完整同意/隐私版本、退款/对账；未声称正式生产容量结论。部署流程见 [`guides/deployment.md`](guides/deployment.md)，保留策略、监控和回滚见 [`operations/runbook.md`](operations/runbook.md)。
