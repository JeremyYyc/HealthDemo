## 1. 结论说明

产品目标、用户闭环、业务状态、异常边界和技术方案已收敛为可实现、可测试的唯一口径。v1.0 冻结的是需求和可观察行为，不代表代码已经验收；实现仍须用迁移、自动化测试、Preview、Smoke 和线上观察证明约束真实成立。任何 S0/S1、权限字段泄漏、迁移失败或核心流程中断都会阻断发布。

## 2. 本轮冻结审查修订

| 原歧义/风险 | 冻结结论 | 同步证据 |
|---|---|---|
| 首次访问、Cookie 丢失和换浏览器无法区分 | 仅用非敏感 `hasSeenSession` 区分本浏览器首次访问与 Cookie 丢失；换浏览器按首次访问 | Funnel 入口状态表、Session API |
| 已有进行中测评时入口年龄选择可能覆盖旧答案 | 客户端先恢复；`POST /sessions` 复用时忽略请求年龄分组 | Session API、US-01 |
| 同一 Session 可并发创建多条进行中测评 | 部分唯一约束；重复创建幂等返回现有记录 | 数据约束、新测评 API |
| 乱序保存与跨字段校验冲突 | 无依赖步骤可乱序；依赖缺失返回 422 且不暂存 | Step API、质量矩阵 |
| 同值重放与乐观锁先后顺序不清 | 先判规范化同值幂等；异值才要求版本一致 | Step API、并发规则 |
| 并发/重复 complete 返回语义不清 | 统一返回同一完成元数据，不内嵌结果、不绕过权限 | Complete API、权限测试 |
| 支付幂等键全局唯一可能跨 Session 泄漏 | 使用 `(sessionId, idempotencyKey)`，并校验请求指纹 | Payment 数据约束、支付 API |
| 支付需要锁 Subscription，但记录可能不存在 | 创建 Session 时同事务创建 `INACTIVE` Subscription | US-01、Session API、数据模型 |
| Demo Payment 状态机与事务回滚冲突 | MVP 只原子写 `SUCCEEDED`；校验失败不建记录，事务失败全回滚 | 支付状态机、异常规格 |
| ACTIVE 到期语义未定义 | MVP `expiresAt = null`，不产生 `EXPIRED` | 权限模型、数据状态机 |
| Free “一般性摘要”字段边界模糊 | 冻结 Free/Full 白名单及四种中性 BMI 摘要 | 权限矩阵、结果页文案 |
| 健康计算舍入和完成日期仍可漂移 | 冻结 `.5` 舍入、热量下限顺序、UTC date-only 和曲线终点 | 算法规格 |
| 403、429、支付状态未知缺少用户恢复动作 | 冻结错误码、`Retry-After`、保留原幂等键和人工重试行为 | Funnel 支付异常表、API 错误表 |
| 多项能力被写成 P1 但主流程/发布门槛依赖 | 重新测评、单位切换、并发保护、错误恢复、健康检查和付费 Seed 提升为 P0 | 主 PRD 范围、API 清单 |
| Session 到期但健康数据无明确删除时间 | 冻结 30 天有效期 + 7 天保留期及版本化清理脚本 | 数据生命周期、部署清单、质量计划 |

## 5. 已知非阻断项

这些不是当前 PRD 决策缺口，而是明确不在 3 天 MVP 内：

- 真实用户研究、真实 Funnel 转化数据和 A/B 实验。
- 真实支付、退款、拒付和财务对账。
- 正式客服、值班平台和自动寻呼系统。
- 大规模负载测试和多地区合规认证。

如果产品从面试演示转为真实公开运营，必须重新 Review，不得直接沿用本次 MVP 冻结结论。

## 6. 冻结与变更控制

- v1.0 的 P0 范围、输入边界、权限字段、状态转换、错误码和验收场景不得在实现中自行改写。
- 纯命名或技术实现可调整，但不得改变外部可观察语义；OpenAPI、Schema、前端状态和测试必须同步。
- 发现阻断性矛盾时先提交 PRD change note，记录原因、受影响文档、迁移/兼容影响和测试变化，再修改实现。
- P1/P2 可删减但不得破坏 P0；任何 P0 删除、权限放宽或健康算法变化都需要重新 Review。
