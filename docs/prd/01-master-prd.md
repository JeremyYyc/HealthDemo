# 个性化健康测评系统——主 PRD

> 版本：v1.0  
> 状态：**MVP Frozen**  
> 目标交付周期：3 天紧凑冲刺

## 1. 执行摘要

### 1.1 问题

用户需要通过一个可信、低摩擦的分步问卷了解基础健康指标和目标路径；评审方需要看到的不只是可填写的表单，而是一套能分步持久化、恢复进度、服务端计算、按订阅权限返回结果，并由自动化测试证明正确性的工程闭环。

### 1.2 方案

构建一个匿名健康测评 Funnel。用户逐步填写性别、目标、年龄、身高、当前体重、目标体重和活动水平；答案每步保存。完成后服务端生成并持久化 BMI、BMR、TDEE、建议摄入量、预计目标日期和预测曲线。非会员只能查看摘要，完成模拟支付后可查看完整结果。

### 1.3 业务与面试价值

- 展示从录入、持久化、计算到权限变化的完整产品闭环。
- 展示 API 设计、数据模型、状态一致性、异常处理和并发控制能力。
- 通过边界测试、集成测试、E2E 和 CI 证明系统行为可重复验证。
- 通过公网链接和本地一键部署降低评审成本。

## 2. 产品目标与非目标

### 2.1 目标

| ID | 目标 | 成功判定 |
|---|---|---|
| G-01 | 用户可顺利完成分步测评 | 从入口到免费结果的关键路径可在线完成 |
| G-02 | 中断后可继续 | 刷新或重开后恢复已保存答案及正确下一步 |
| G-03 | 健康结果可信且可解释 | 所有计算在服务端完成，公式、边界和舍入规则有测试 |
| G-04 | 免费与会员权限隔离 | 非会员响应中不存在预测曲线等保护字段 |
| G-05 | 支付形成闭环 | 调用模拟支付后，订阅生效且重新取结果返回完整数据 |
| G-06 | 可评审、可复现 | 有公网 URL、README、本地部署、测试命令、ER 图和 API 文档 |

### 2.2 非目标

- 真实医疗诊断或个体化医疗建议。
- 真正的 Stripe/支付宝/微信支付及退款。
- 注册、登录、找回密码、社交登录。
- Pilates 视频、食谱、AI 教练、长期体重打卡。
- 1:1 复制 BetterMe 的页面、题库或商业算法。
- 复杂后台运营系统、优惠券、套餐和订单管理。

## 3. 用户与核心场景

### 3.1 主要用户

**访客用户**：希望快速获得健康摘要，可能中途离开或刷新页面。  
**已解锁用户**：完成模拟支付，希望查看完整结果与预测曲线。  
**项目评审者**：需要在线走通流程，也需要本地复现、调用 API、运行测试并对比权限差异。

### 3.2 Jobs to Be Done

- 当我想了解体重目标的基础路径时，我希望用几分钟完成简单问卷，从而获得清晰摘要。
- 当我中途被打断时，我希望回来后从上次位置继续，而不是重新填写。
- 当我解锁报告后，我希望立即看到完整数值和预测，不需要重新测评。
- 当我评审项目时，我希望能快速验证异常输入、恢复流程和支付前后差异。

### 3.3 角色与责任（RACI）

本项目由一名候选人独立交付，因此同一人可能承担多个角色，但责任不能省略。

| 工作项 | Responsible（执行） | Accountable（最终负责） | Consulted（咨询） | Informed（知会） |
|---|---|---|---|---|
| 需求与范围冻结 | 产品负责人（候选人） | 候选人 | 面试题/评审反馈 | 评审者 |
| UX、前后端与数据库 | 开发负责人（候选人） | 候选人 | 官方技术文档 | 评审者 |
| 测试与发布门槛 | 质量负责人（候选人） | 候选人 | CI 结果 | 评审者 |
| Vercel/Supabase 配置 | 部署负责人（候选人） | 候选人 | 平台状态页/文档 | 评审者 |
| 线上故障、数据重置与补偿 | 发布值守人（候选人） | 候选人 | 平台日志 | 评审者 |

挑战期间不存在独立客服、测试岗或运维岗。README 是评审者的第一支持入口；S0/S1 问题由发布值守人处理并记录。

## 5. 端到端用户旅程

```text
访问入口
→ 选择年龄分组并创建匿名 Session/Assessment
→ 逐步回答并自动保存
→ 刷新或重开时恢复
→ 提交完成
→ 服务端校验、计算和持久化
→ 查看免费摘要与锁定区域
→ 调用模拟支付
→ 重新获取结果
→ 查看完整报告和预测曲线
```

详细页面与异常流程见 [02-funnel-and-screen-spec.md](./02-funnel-and-screen-spec.md)。

## 6. 用户故事与验收标准

### US-01 开始匿名测评

作为访客，我希望无需注册即可开始，以便降低体验门槛。

- 选择年龄分组后创建或复用有效 Session。
- 新 Session 在同一事务创建一个 `IN_PROGRESS` Assessment 和一个 `INACTIVE` Subscription，保证支付并发时始终有可锁定权益行。
- Session token 不通过 URL 或前端可读存储暴露。
- Session Cookie 有效期为 30 天；清理 Cookie、使用其他浏览器或过期后无法恢复旧进度。
- 已有进行中测评时返回原测评；只有已完成测评时由用户明确选择查看结果或创建新测评。
- 每个 Session 同时最多一个进行中测评；重复点击“重新测评”不得创建多条记录。

### US-02 分步保存

作为访客，我希望每完成一步就自动保存，以免丢失进度。

- 非法输入返回 4xx，数据不落库，页面不前进。
- 保存成功后返回当前版本、完成步骤和下一步。
- 重复提交同一有效答案不会产生重复记录或损坏状态。
- 相同规范化答案即使携带旧版本也可幂等返回当前状态；旧版本提交不同答案返回 409，绝不覆盖新值。
- 修改上游答案导致下游答案非法时，服务端使对应下游步骤失效并返回 `invalidatedSteps`。
- 乱序保存允许，但依赖前置答案的步骤在前置缺失时返回 422 `STEP_PREREQUISITE_MISSING`，不落库。

### US-03 恢复进度

作为访客，我希望重访时继续未完成测评。

- 服务端返回已保存答案、状态和下一步。
- 前端跳到第一处缺失或已失效的必填步骤。
- 服务端数据为真相来源，不依赖单一浏览器内存状态。

### US-04 完成测评

作为访客，我希望提交后获得个性化摘要。

- 缺少必填项、跨字段不一致或已完成重复提交均得到确定性响应。
- Assessment 与 Result 的状态变更在同一事务中完成。
- 计算结果与 Assessment 建立唯一关联并可重复读取。
- complete 必须携带当前版本；版本不一致不得基于旧答案计算。
- 已完成后的重复 complete，以及并发 complete 的失败方，均返回同一份完成元数据；完整结果仍只能通过结果接口按权限读取。

### US-05 免费结果

作为非会员，我希望先看到有价值的摘要，再决定是否解锁。

- 返回 BMI、BMI 分类、一般性摘要、解锁提示。
- 响应 JSON 中不存在预测曲线、精确目标日期等受保护字段。
- 前端隐藏不等于权限控制；裁剪必须发生在服务端。

### US-06 模拟支付与解锁

作为访客，我希望完成模拟支付后立即查看完整结果。

- 支付请求可重放且不会生成冲突权益。
- 成功后 Subscription 为 `ACTIVE`，Payment 有可审计记录。
- 再次获取同一结果时返回完整 DTO。
- 同一 Session 的权益为全局权益；一次激活解锁其所有已完成测评。
- 页面支付不传递服务端 secret，依赖 HttpOnly Session、同源校验、幂等键和限流。
- 幂等键按 Session 隔离；相同文本键绝不能跨 Session 命中或泄露 Payment 信息。

### US-07 评审与复现

作为评审者，我希望快速验证项目质量。

- 公网 URL 可走完全流程。
- README 提供本地启动、迁移、Seed、测试和 cURL。
- 提供一个已付费测试 Session，以及通过受控 review code 换取该 Session HttpOnly Cookie 的复验方法。

## 7. 非功能要求

| 类别 | MVP 要求 |
|---|---|
| 性能 | 普通 API 在正常网络下 P95 目标 < 800ms；结果生成不依赖人为后端 sleep |
| 可靠性 | 关键写入使用事务；重复请求可安全处理；失败不推进前端步骤 |
| 安全 | 30 天 HttpOnly Cookie；生产环境 Secure；SameSite=Lax；写接口校验 Origin；服务端校验；禁止客户端指定其他用户/会话身份 |
| 隐私 | 仅收集完成测评必要的数据；日志不打印 session token 和完整健康数据；Session 到期 7 天后按脚本清理关联数据 |
| 可访问性 | 键盘可操作、输入有 label、错误可被读屏理解、颜色不是唯一状态提示 |
| 兼容性 | 最新桌面与移动端 Chrome/Safari 的基础流程可用 |
| 可观测性 | 统一错误格式；关键状态转换有结构化日志；提供 `/api/health` |
| 可维护性 | TypeScript strict；分层业务逻辑；数据库迁移受版本控制 |

### 8.1 指标口径

| 指标 | 计算口径 | 排除项 | 负责人 |
|---|---|---|---|
| 测评完成率 | 同一环境、同一版本内 `completed Assessment 数 / started Assessment 数` | Seed、自动化测试、重复事件 | 产品负责人 |
| 步骤流失率 | `进入某步骤但未成功保存的 Assessment 数 / 进入该步骤的 Assessment 数` | 网络重试产生的重复事件 | 产品负责人 |
| 支付解锁成功率 | `产生首次 ACTIVE 的 Session 数 / 发起 Demo payment 的非会员 Session 数` | 已 ACTIVE 的重复点击 | 开发负责人 |
| 恢复成功率 | `返回有效进行中 Assessment 的恢复请求数 / 携带有效未过期 Cookie 的恢复请求数` | 无 Cookie、过期 Cookie | 开发负责人 |
| API 错误率 | 非预期 5xx 请求数 / 全部 API 请求数 | 预期 4xx 校验错误 | 发布值守人 |

事件必须携带 `eventName`、`occurredAt`、`environment`、`appVersion`、`assessmentId`（可用非敏感公共 ID）和 `requestId`，不得携带 Session token、完整健康答案或保护结果字段。MVP 不执行 A/B 实验，仅建立基线；如未来实验，需另行定义假设、分流、样本量和停止条件。

MVP 指标看板不引入新的第三方分析平台：结构化事件进入应用日志，由部署负责人按环境和 `appVersion` 查询并在验收记录中汇总。若事件埋点因时间被降为 P2，发布指标只使用 CI、E2E、健康检查和人工 smoke，不以缺失的业务数据宣称转化效果。

## 11. 已冻结产品决策

1. `MAINTAIN_WEIGHT` 的目标体重容差采用 ±2kg。
2. 免费版同时展示精确 BMI 和 BMI 分类；BMR、TDEE、建议摄入、精确日期与曲线属于保护字段。
3. 模拟支付仅限当前 HttpOnly Session，通过 Origin/CSRF 防护、共享限流和幂等键控制；浏览器不持有服务端 secret。
4. 已完成测评不可修改，只能创建新测评。
5. 预测速度采用固定速率模型，最大预测周期为 104 周。
6. 年龄分组选项计入 8 个正式问卷步骤。
7. Subscription 归属于 Session，一次激活解锁该 Session 下所有已完成测评。
8. Session Cookie 有效期为 30 天；Cookie 丢失后普通用户无法恢复。
9. 已付费演示 Session 通过受控 review code 交换 HttpOnly Cookie，不通过 URL 暴露真实 Session token。
10. 本项目是 Greenfield MVP，没有存量用户或历史生产数据；历史 Result 通过 `algorithmVersion` 保持可解释，Schema 仅使用向前迁移，不在部署时自动重算旧结果。
11. MVP 不提供真实退款/撤销；Demo payment 错误由发布值守人通过受控 Seed/reset 脚本重建合成数据，不直接手工改生产表。
12. 同一 Session 最多存在一个 `IN_PROGRESS` Assessment；新建请求在已有进行中记录时返回现有记录。
13. 步骤保存的幂等判定以规范化领域值为准：当前值相同则返回 200 和当前版本；当前值不同且版本过期则返回 409。
14. 依赖型步骤缺少前置答案时返回 422，不暂存不可验证的答案；`target-weight` 依赖 goal、height、current-weight。
15. Demo 支付幂等键使用 `(sessionId, idempotencyKey)` 复合唯一约束；ACTIVE 订阅在 MVP 中 `expiresAt = null`，不会自动过期。
16. 浏览器只可保存非敏感 `hasSeenSession` 标记以区分首次访问和 Cookie 丢失；不得在可读存储保存 token、Assessment 答案或结果。
17. `complete` 的重复/并发成功响应只返回 Assessment 完成元数据和结果 URL，不内嵌 Full Result，避免绕过结果权限。
18. Session 创建 30 天后失效，关联演示数据最迟再保留 7 天；公开演示期至少每 7 天运行清理，评审结束后再清理一次。

## 12. 总体验收定义

只有同时满足以下条件才可标记 MVP 完成：

- 所有 P0 用户故事验收通过。
- 非会员响应经测试确认不含保护字段。
- 中断恢复、乱序、重复提交和并发更新都有明确行为并被测试。
- 首次访问、无 Cookie、过期/篡改 Cookie、已有进行中测评、只有已完成测评和重复新建均有确定入口行为。
- 上游答案修改会正确使非法下游答案失效，进度指向第一处缺失或失效步骤。
- 线上可完整演示，模拟支付可重放。
- 新环境按照 README 能启动应用并运行测试。
- ER 图、API 文档、测试说明、AI 使用复盘和已知限制齐全。
