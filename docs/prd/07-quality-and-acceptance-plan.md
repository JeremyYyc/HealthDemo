# 质量保障与验收计划

> 版本：v1.0 MVP Frozen  
> 原则：测试是交付基本盘，不是补充材料。

## 1. 质量目标

- 核心算法的正常、边界和非法输入有确定行为。
- 分步保存、恢复、乱序、重复和并发均经过验证。
- 非会员无法从任何结果响应得到保护字段。
- 模拟支付前后权限变化有端到端证据。
- 所有检查可通过一条命令和 CI 重复运行。

## 2. 测试分层

| 层级 | 工具建议 | 目标 | 重点 |
|---|---|---|---|
| 单元 | Vitest | 快速验证纯函数 | 公式、边界、舍入、单位转换、DTO 裁剪 |
| Service | Vitest | 验证业务状态和依赖交互 | 保存规则、状态转换、幂等、权限 |
| 集成 | Vitest + 测试 PostgreSQL | 验证真实数据约束和事务 | 恢复、并发、唯一约束、回滚 |
| API | Vitest/HTTP 测试 | 验证路由、状态码和响应契约 | Zod、Cookie、错误格式、字段白名单 |
| E2E | Playwright | 验证真实浏览器关键路径 | 问卷→免费结果→支付→完整结果 |

Vitest 适合作为主测试运行器：与 TypeScript/Vite 生态配置轻、运行快，并具备断言、mock 和覆盖率能力。Playwright 只覆盖少量关键浏览器流程，避免把所有边界都放到慢且脆弱的 E2E。

## 3. P0 测试矩阵

### 3.1 健康计算

- 正常男女输入与五档活动系数。
- BMI 分类边界与舍入。
- 年龄/身高/体重/目标体重的最小值、最大值、越界、缺失和非法类型。
- `NaN`、`Infinity` 直接调用领域函数时被拒绝。
- 减重/维持/增重的目标方向和交叉字段校验。
- 格式/范围错误返回 400，格式合法但跨字段业务规则失败返回 422 且定位对应字段。
- 热量安全下限、目标日期、跨年和曲线终点。

### 3.2 分步保存与恢复

- 顺序保存若干步，模拟中断后 GET 恢复。
- 重复提交相同答案。
- 旧版本重放相同规范化答案返回当前状态且不递增版本；旧版本提交不同答案返回 409。
- 修改已完成步骤。
- 修改 `ageRange` 后使不匹配的 `age` 失效。
- 修改 `goal/height/currentWeight` 后使非法 `targetWeight` 失效，并返回 `invalidatedSteps`。
- 乱序提交后 `nextStep` 仍指向第一缺口。
- 乱序提交依赖型步骤且前置缺失时返回 422、不落库。
- 两个请求使用同一版本并发更新，只允许一个成功。
- 非法更新不写库、不递增版本。
- 已完成测评禁止修改。

### 3.3 完成事务

- 必填完整时生成唯一 Result 并完成 Assessment。
- 缺字段或跨字段非法时不生成 Result。
- 计算/写入故障时事务回滚。
- complete 使用旧版本时返回 409；与最后一步保存并发时不得基于旧答案计算。
- 相同版本并发 complete 不生成第二条 Result，失败方返回已有结果。
- 已完成后重复 complete 只返回同一完成元数据，不内嵌 Full Result。

### 3.4 权限与支付

- 非会员响应精确匹配 Free DTO，保护字段不存在。
- 会员响应包含 Full DTO。
- 无 Session、其他 Session、未完成测评均被拒绝。
- 支付成功改变 Subscription；重新 GET 结果升级为 Full。
- 相同幂等键重放、两个不同幂等键并发支付、事务回滚。
- 同 Session 已持久化的激活 Payment 键换 Assessment 返回 409；ACTIVE 后 no-op 新键不建记录；两个 Session 使用相同文本键互不影响且不泄露 Payment。
- 已激活 Session 使用新幂等键不创建第二条成功 Payment。
- review code 交换已付费演示 Session 的成功、错误、超限和越权场景。

### 3.5 浏览器 E2E

1. 新访客完成 8 步，看到免费摘要。
2. 中途刷新，答案和步骤恢复。
3. 输入非法目标体重，被阻止并看到错误。
4. 完成 Demo payment，原结果页刷新为完整报告。
5. Session Cookie 过期/丢失时明确提示无法恢复并可开始新测评。
6. 首次访问不误报进度丢失；有非敏感历史标记但无有效 Cookie 才显示丢失提示。
7. 直接访问过早/过晚步骤和结果路由时按服务端 `nextStep`/状态守卫跳转。

| 需求 | 主要证据 |

## 5. 覆盖率与发布门槛

不以单一覆盖率数字代替测试质量。MVP 冻结门槛：

- 所有 P0 用例通过。
- statements/lines/functions 总体覆盖率 ≥80%，核心计算与权限模块分支覆盖率 ≥90%。
- TypeScript 类型检查、lint、单元/集成测试均通过。
- 数据库迁移可在空库向前执行。
- 关键 E2E 在部署前至少一次稳定通过。
- API 响应快照确认免费字段无泄漏。

## 6. 冻结的一键命令

```bash
npm test
npm run test:integration
npm run test:e2e
npm run test:coverage
npm run check
```

`npm test` 至少运行无需额外手工准备的核心测试。完整测试若需 Docker，应在 README 明确一键启动测试数据库的方式。

## 7. 测试数据与隔离

- 使用独立测试数据库，禁止连接开发/生产库。
- 每个测试使用独立 ID/事务或清晰清理策略。
- 固定时间与随机数种子，避免脆弱快照。
- 日期测试固定为 UTC date-only，覆盖跨月、跨年、闰年和不同时区运行环境。
- Seed 提供 unpaid 与 paid 两套演示 Session，但测试自身不依赖共享 Seed 状态。
- CI 不输出数据库 URL、Cookie、review code、演示 token 或其摘要。
- 写接口覆盖错误 Content-Type、空/畸形 JSON、超过 16KB 请求体、跨站 Origin 和过期/篡改 Cookie。
- 写接口覆盖 Origin 缺失、429 `Retry-After`、跨实例共享限流，以及 cURL 携带合法 Origin 的成功场景。
- 数据约束测试覆盖每 Session 一个进行中测评、一个 Subscription、一个首次成功 Payment 及 Session 内幂等复合唯一。
- 清理脚本覆盖 dry-run、30+7 天边界、显式删除顺序、未到期隔离和重复执行幂等。

## 8. 暂不覆盖及理由

- 真实支付供应商签名/退款：不在挑战范围。
- 大规模压测：3 天 MVP 无真实容量目标；仅验证基本并发冲突。
- 多地区隐私合规认证：产品未正式运营；文档列出未来要求。
- 全浏览器矩阵：优先最新版 Chrome/Safari 和移动布局。
- 竞品全部分支：不做 1:1 复刻。

## 9. 缺陷优先级

| 等级 | 定义 | 发布处理 |
|---|---|---|
| S0 | 数据泄漏、他人结果可访问、数据损坏 | 必须阻断发布 |
| S1 | 主流程/支付/恢复不可用，算法严重错误 | 必须阻断发布 |
| S2 | 局部错误或非关键兼容问题 | 评估后修复或记录 |
| S3 | 文案、轻微样式问题 | 可记录已知限制 |

## 10. 监控、告警与处理路径

| 信号 | 阈值/触发条件 | 处理动作 | 负责人 |
|---|---|---|---|
| `/api/health` | 连续 3 次失败 | 停止新演示，检查应用和数据库状态 | 发布值守人 |
| API 5xx | 5 分钟内 ≥5 次或错误率 >5% | 检查 requestId/日志；必要时回滚部署 | 发布值守人 |
| P95 延迟 | 10 分钟内持续 >800ms | 检查冷启动、连接池和慢查询；降级非核心展示 | 开发负责人 |
| 数据库连接错误 | 任一 `too many connections`/连接超时集中出现 | 停止发布，检查 pooler/客户端实例 | 部署负责人 |
| 权限字段泄漏 | 任一自动化或人工检查失败 | S0，立即下线结果接口或回滚 | 开发负责人 |
| Demo exchange 异常 | 429 激增、错误 code 尝试集中出现 | 临时关闭接口并轮换 review code | 发布值守人 |

MVP 不建设独立客服系统。评审者通过 README 的故障排查与仓库 Issue/交付联系渠道反馈；发布值守人记录 `requestId`、发生时间、环境、复现步骤和处理结果。不得要求用户发送 Cookie、token 或完整健康数据。
